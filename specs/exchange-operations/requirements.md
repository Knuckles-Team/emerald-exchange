# EMERALD-OPS requirements

Every requirement this specification owns, with the proof that closes it. Delivery state and
public evidence for each ID are recorded in [`status.json`](status.json); this file defines what
each ID means. The design is in [`spec.md`](spec.md) and [`plan.md`](plan.md), the test contract
in [`test-spec.md`](test-spec.md), and the work order in [`tasks.md`](tasks.md).

| ID | Requirement | Verification |
|---|---|---|
| `EMERALD-OPS-R001` | **Read-only exchange operations are per-operation tools.** Stage: served MCP tools. Entry: `tools/call` on `emerald_exchange_get_quote`, `_get_historical`, `_get_positions`, `_get_account`, `_get_order_status` and `_exchanges`. Caller: `emerald_exchange/mcp_server.py::get_mcp_instance` → `register_tool_surface` with `verbose_targets` → `emerald_exchange/exchange_operations.py::ExchangeReadOperations` → the active `ExchangeBackend` method (the venue call). Each read is one typed tool. No write operation is served unguarded: submit, cancel, connect and disconnect exist only behind `RiskGuard` in `emerald_orders`. Emerald computes nothing here; every calculation is medulla's through `scion_sdk.compute`. Arbora reads markets, events and orders through nine further per-operation tools (EMERALD-OPS-R005). Refusals: `provider_unavailable` without the provider message. Writes: none. Depends on: none. | Test: `tests/test_order_guard.py::test_per_operation_surface_is_read_only` (L3) lists the served tools. `test_no_unguarded_order_tool_is_served` asserts that no write tool is registered. |
| `EMERALD-OPS-R002` | **Fleet name.** `pyproject.toml` declares `emerald-exchange-mcp` as the single `scion_sdk.connector` entry point. The content pack, the manifest `connector`, the fingerprints and the ingest binding all carry `emerald-exchange-mcp`. Proving test: `tests/test_fleet_name.py::test_connector_name_is_the_fleet_name`. | Every connector name in the package is `emerald-exchange-mcp`. |
| `EMERALD-OPS-R003` | **Alpaca account reads retain provider identity and fail closed.** The served account read exposes the provider account ID and currency. Missing identity, invalid currency, non-finite values, or provider read failure do not produce a fabricated empty account or positions. Documented provider transport and API errors are reported without the provider message. | `tests/test_alpaca_account_integrity.py` covers the provider adapter, real in-process MCP tool, invalid responses and redacted transport failures. |
| `EMERALD-OPS-R004` | **Declare an Alpaca account snapshot source.** An explicit source serves one account with its associated positions, keyed by the provider account ID. It refuses a non-Alpaca backend or an incomplete provider read. This source does not itself prove durable re-import. | `tests/test_alpaca_account_integrity.py::test_snapshot_source_is_declared_and_served` and `test_snapshot_source_refuses_incomplete_account_or_position_reads`. |
| `EMERALD-OPS-R005` | **Prediction-market and order read tools for arbora.** Stage: served tools. Entry: nine per-operation MCP tools `emerald_exchange_list_markets`, `_search_markets`, `_get_market`, `_list_events`, `_search_events`, `_get_event`, `_list_orders`, `_search_orders` and `_get_order`. Caller: arbora `FleetFinanceReadPort` (ARBORA-DATA-MARKET-R003.6) → fleet call → the tool → `emerald_exchange/exchange_operations.py::ExchangeReadOperations` → `emerald_exchange/prediction_markets.py::PredictionMarketReader` and `ExchangeBackend.list_orders`. Each tool returns the provider records with `source`, `as_of`, `session`, currency, unit and provenance, and fabricates none. It computes nothing and accepts the filters of ARBORA-DATA-MARKET-R003.1 to R003.3. Refusals: `provider_unavailable` with no provider message. Writes: none. Depends on: EMERALD-OPS-R001. | Test: `tests/test_market_read_tools_served.py::test_nine_read_tools_return_provider_records` (L3) runs the tools against a recorded venue response. It asserts the fields and the absence of any order call. |
| `EMERALD-OPS-R006` | **Order routing requires the arbora confirmation receipt.** The order-routing tool must refuse an order without a receipt. The receipt comes from `ARBORA-OPS-R070` and names the same admission digest. Caller: the served `place_order` tool. Refusal: `ORDER_CONFIRMATION_REQUIRED`. Depends on: `ARBORA-OPS-R070`. | Test: a served tool test against a recorded venue response routes with a receipt and refuses without one. |
| `EMERALD-OPS-R007` | **Quant analysis bindings use numeric.evaluate.** Stage: served MCP tools. Caller: `emerald_exchange/analyses.py::ou_stat_arb_signal` and `hedge_beta` → `emerald_exchange/_engine.py::run_analysis` → `scion_sdk.compute` → `NumericEvaluate`. Rule: in `emerald_exchange/ontology/quant.ttl` replace each `fin:servedBy "finance.<kernel>"` of the kernels in `MEDULLA-FINANCE-PRIMITIVES-R002` with `fin:servedBy "numeric.evaluate"` and a `fin:servedOp` value. Refusal: an unserved analysis still returns the `engine_error` payload. Depends-on: `MEDULLA-FINANCE-PRIMITIVES-R002.2.5`, `SCION-FINANCE-SOURCES` `SCION-FINANCE-SOURCES-R902`. | `tests/test_quant_bindings.py::test_every_kernel_binding_uses_numeric_evaluate` (L3) reads `quant.ttl` and calls `emerald_statarb` against a recorded engine response. |
| `EMERALD-OPS-R008` | **Order routing requires an admission receipt.** Stage: served order tool. Caller: `emerald_exchange/mcp/mcp_orders.py` order tool → verify `OrderAdmissionReceipt` digest from `MEDULLA-FINANCE-PRIMITIVES-R015.1.3` → venue call. Refusal: a missing or mismatched receipt returns `ADMISSION_REQUIRED` and no venue call occurs. Depends-on: `MEDULLA-FINANCE-PRIMITIVES-R015.1.3`. | `tests/test_order_admission.py::test_order_refused_without_receipt` (L3) against a recorded venue response. |
| `EMERALD-OPS-R009` | **Pattern and attribution actions call the engine.** Stage: served tool. Entry: MCP tool `emerald_signals` actions `pattern_classify` and `profit_attribution`. Caller: `emerald_exchange/mcp/mcp_signals.py::emerald_signals` → `emerald_exchange/analyses.py` → `scion_sdk.compute.finance.pattern_classify` and `profit_attribution` (SCION-FINANCE-SOURCES-R904) → the medulla methods of MEDULLA-FINANCE-PRIMITIVES-R750.754. The tool reads bars from the active backend (`backend.get_historical`) and sends them unchanged. It holds no pattern rule and no attribution formula. Refusals: `engine_unavailable`, and the engine codes pass through. Depends on: MEDULLA-FINANCE-PRIMITIVES-R750.754. | Test: `tests/test_research_kernels_served.py::test_signal_actions_reach_engine_methods` (L3) drives both actions against a recorded venue response and a recorded engine reply. It asserts results and codes. |
| `EMERALD-OPS-R010` | **Research record tools.** Stage: served tool. Entry: MCP tools `emerald_debate` (existing, in `emerald_exchange/mcp/mcp_debate.py`) and new `emerald_journal`, with actions `record_sentiment`, `record_geopolitical_risk` and `record_strategy_card`. Caller: the tool function → `scion_sdk.finance.research_records.ResearchRecordSink` (SCION-FINANCE-SOURCES-R903) → medulla record entries of MEDULLA-FINANCE-PRIMITIVES-R751.754. The tool gathers the source text and the component scores from the venue and the user. It sends no fused score. Register `emerald_journal` in the `registrars` list of `emerald_exchange/mcp_server.py`. Refusals: `engine_unavailable`, and the medulla codes pass through. | Test: `tests/test_research_records_served.py::test_debate_and_card_tools_write_through_the_sink` (L3) drives the tools against a recorded engine reply. It asserts the record ids and the refusal codes. |
| `EMERALD-OPS-R011` | **Position sizing tool calls the engine.** Stage: served tool. Entry: MCP tool `emerald_risk` action `kelly`. Caller: `emerald_exchange/mcp/mcp_risk.py::_dispatch` → `emerald_exchange/analyses.py::position_size` → `emerald_exchange/_engine.py::run_analysis("KellySizing")` → `scion_sdk.compute.finance.position_size` (SCION-FINANCE-SOURCES-R904) → `Method::FinancePositionSize`. Remove `RiskGuard.kelly_criterion` in `emerald_exchange/risk_guards.py` and its callers. The tool returns the engine value and the cap the engine applied. Venue and order code stay in emerald. Refusals: `{"error": "engine_unavailable"}` when the engine is unreachable, and the engine code `SIZING_INPUT_INVALID` for a bad accuracy. No local fallback. Depends on: MEDULLA-FINANCE-PRIMITIVES-R900.3. | Test: `tests/test_position_size_served.py::test_kelly_action_returns_engine_value_and_refuses_without_engine` (L3) drives the tool with a recorded engine reply. It asserts that no local formula remains. |
| `EMERALD-OPS-R012` | **Distribution-shift analysis calls the engine.** Stage: served tool. Entry: MCP tool `emerald_signals` action `distribution_shift`. Caller: `emerald_exchange/mcp/mcp_signals.py::emerald_signals` → `emerald_exchange/analyses.py::distribution_shift` → `scion_sdk.compute.finance.distribution_shift` (SCION-FINANCE-SOURCES-R904) → `Method::FinanceDistributionShift`. Replace the `refuse("DistributionShiftAnalysis")` body. Add the analysis binding to `emerald_exchange/ontology/quant.ttl` so `EngineCompute.select_algorithms` finds `FinanceDistributionShift`. The default `threshold` is 0.1 and stays in the tool signature as a caller value. Refusals: engine codes `SHIFT_SAMPLE_EMPTY` and `SIZING_INPUT_INVALID` pass through. Depends on: MEDULLA-FINANCE-PRIMITIVES-R900.3. | Test: `tests/test_distribution_shift_served.py::test_shift_action_reaches_engine_method` (L3) drives the tool against a recorded engine reply. It asserts the statistic, `shifted` and the refusal codes. |
| `EMERALD-OPS-R013` | **Banking kernels tool calls the engine.** Stage: served tool. Entry: new MCP tool `emerald_banking` with actions `aml_screen`, `capital_ratios`, `expected_loss` and `settlement_chain`. Caller: `emerald_exchange/mcp/mcp_banking.py::emerald_banking` → `emerald_exchange/analyses.py` → `scion_sdk.compute.finance` (SCION-FINANCE-SOURCES-R904) → the four medulla methods of MEDULLA-FINANCE-PRIMITIVES-R901.3. Register the domain in the `registrars` list of `emerald_exchange/mcp_server.py` under tag `banking` and env `BANKINGTOOL`. The tool holds no formula and no threshold. Refusals: `engine_unavailable`, and the engine codes pass through. Depends on: MEDULLA-FINANCE-PRIMITIVES-R901.3. | Test: `tests/test_banking_served.py::test_each_action_reaches_its_engine_method` (L3) drives the tool against recorded engine replies. It asserts the four results and the refusal codes. |
| `EMERALD-OPS-R014` | **Served wallet operation tool composes the SDK proof gate.** Subsystem: emerald-exchange served tools. Caller: arbora `finance.wallet_operation` → fleet call → `wallet_operation_apply`. The tool accepts a `WalletExecutionEnvelope` and calls `scion_sdk.writeback_sinks.core.run_writeback` with `ops["wallet_envelope"]`. The venue call runs only inside the sink after the SDK proof gate and governed apply succeed. The tool holds no signing key for the user wallet. It returns the write-back attempt fields unchanged. It refuses with the SDK refusal codes of SCION-GOVERNED-WRITEBACK-R001.4. Depends on: SCION-GOVERNED-WRITEBACK-R001.3. | Test: `tests/test_wallet_operation_served.py::test_tool_passes_envelope_and_refuses_without_proof` (L3). It runs against a recorded venue response and asserts zero venue calls on every refusal. |
