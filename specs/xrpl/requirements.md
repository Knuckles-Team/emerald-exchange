| `CONN-EMERALD-EXCHANGE-XRPL-R001` | **Agent wallet create, load and sign.** Stage: connector effect. Entry: MCP tool registered by `emerald_exchange/mcp/mcp_xrpl.py::register_xrpl_tools` in the `registrars` list of `emerald_exchange/mcp_server.py` under tag `xrpl` and env `XRPLTOOL`. Tools: `emerald_xrpl_wallet_create`, `emerald_xrpl_wallet_load`, `emerald_xrpl_sign`. Caller: tool → `emerald_exchange/xrpl/wallet.py::create_wallet`, `load_wallet`, `sign`. `create_wallet` writes the seed to the SDK secret facade and returns the address only. `load_wallet` resolves an address reference to a seed; no seed appears in a result or a log. `sign(tx, wallet_ref, preview=True)` returns the decoded transaction, the fee and the account sequence, and no signature. A real signature needs the confirmation of ARBORA-DATA-MARKET-R007 and a `WalletBusinessIntent` that binds account, network, wallet and operation. Scoped auto-sign applies only when the operation, amount and destination match an entry of `xrpl.auto_sign` (Fixed, default empty). Network default `testnet`. Refusals: `WALLET_NOT_FOUND`, `SIGN_NOT_CONFIRMED`, `ATTRIBUTION_MISSING`. Writes: the secret entry on create. Depends on: R007, R008, R009. | Test: `tests/test_xrpl_wallet.py::test_wallet_create_load_sign_preview` (L3) runs against a recorded testnet response. It asserts the preview, the refusal without confirmation and that no seed leaks. |
| `CONN-EMERALD-EXCHANGE-XRPL-R002` | **XRP and RLUSD payments.** Stage: connector effect. Entry: MCP tool registered by `emerald_exchange/mcp/mcp_xrpl.py::register_xrpl_tools` in the `registrars` list of `emerald_exchange/mcp_server.py` under tag `xrpl` and env `XRPLTOOL`. Tools: `emerald_xrpl_send_xrp`, `emerald_xrpl_send_rlusd`. Caller: tool → `emerald_exchange/xrpl/payments.py::send_xrp`, `send_rlusd` → `risk.check_spend` → `attribution.attach` → preview. | `CONN-EMERALD-EXCHANGE-XRPL-R003` | **Trust lines.** Stage: connector effect and read. Entry: MCP tool registered by `emerald_exchange/mcp/mcp_xrpl.py::register_xrpl_tools` in the `registrars` list of `emerald_exchange/mcp_server.py` under tag `xrpl` and env `XRPLTOOL`. Tools: `emerald_xrpl_trust_set`, `_trust_raise`, `_trust_remove`, `_trust_get`. Caller: tool → `emerald_exchange/xrpl/trust_lines.py` → `emerald_exchange/xrpl/account.py::account_lines` for reads. | `CONN-EMERALD-EXCHANGE-XRPL-R004` | **Escrow-gated work.** Stage: connector effect. Entry: MCP tool registered by `emerald_exchange/mcp/mcp_xrpl.py::register_xrpl_tools` in the `registrars` list of `emerald_exchange/mcp_server.py` under tag `xrpl` and env `XRPLTOOL`. Tools: `emerald_xrpl_escrow_create`, `_escrow_release`, `_escrow_refuse`, `_escrow_status`. Caller: tool → `emerald_exchange/xrpl/escrow.py`. Every mutating call previews first and executes only inside the governed apply composition after the confirmation of ARBORA-DATA-MARKET-R007. Escrows hold XRP only. Create locks funds against a work order ID with a crypto-condition. It sets `CancelAfter` to now plus `xrpl.escrow.timeout_s` (default 86400, [3600, 2592000], seconds). Release on acceptance submits `EscrowFinish` with the fulfillment. Refuse records the refusal and reports `cancel_available_at`; `EscrowCancel` runs at the first ledger time at or after `CancelAfter`. Timeout cancels the same way. Refusals: `ESCROW_NOT_FOUND`, `ESCROW_NOT_YET_CANCELABLE`, `ESCROW_ASSET_UNSUPPORTED`. Writes: one ledger transaction per step. Depends on: R001, R007, R008. | Test: `tests/test_xrpl_escrow.py::test_escrow_release_refuse_expire` (L3) runs recorded release, refusal and expiry paths and asserts each refusal code. |
| `CONN-EMERALD-EXCHANGE-XRPL-R005` | **Native DEX and AMM market operations.** Stage: connector effect and read. Entry: MCP tool registered by `emerald_exchange/mcp/mcp_xrpl.py::register_xrpl_tools` in the `registrars` list of `emerald_exchange/mcp_server.py` under tag `xrpl` and env `XRPLTOOL`. Tools: `emerald_xrpl_offer_create`, `_offer_cancel`, `_book_offers`, `_amm_swap`. Caller: tool → `emerald_exchange/xrpl/dex.py`. Every mutating call previews first and executes only inside the governed apply composition after the confirmation of ARBORA-DATA-MARKET-R007. Inspect reads `book_offers`. Emerald holds no impact formula. Without the engine the preview returns `engine_unavailable` for that field only. Refusals: `OFFER_NOT_FOUND`, `NO_PATH`, `SPEND_LIMIT_EXCEEDED`. Writes: one ledger transaction per mutation. Depends on: R001, R007, R008. | Test: `tests/test_xrpl_dex.py::test_dex_offer_and_amm_swap` (L3) runs recorded offers, a swap and an engine reply. It asserts the preview, the impact field and each refusal. |

| `CONN-EMERALD-EXCHANGE-XRPL-R007` | **Agent attribution and audit trail.** Stage: connector safety. Caller: every mutating tool → `emerald_exchange/xrpl/attribution.py::attach(tx, request_id)`; read tool `emerald_xrpl_audit_trail` → `audit_trail(address)`. `attach` sets the `SourceTag` from `xrpl.source_tag` and one memo: type `agent-attribution`, data `<agent_id>|<request_id>`, both hex-encoded and at most 256 bytes. `audit_trail` reads `account_tx` and returns hash, tag, agent, request and ledger index. | `CONN-EMERALD-EXCHANGE-XRPL-R008` | **Spending-limit checks and kill-switch.** Stage: connector safety. Caller: every outbound value → `emerald_exchange/xrpl/risk.py::check_spend(amount, currency)` before signing; tools `emerald_xrpl_spend_status` and `emerald_xrpl_halt`. The check compares the amount with the per-transaction limit and with the trailing 24-hour total. The total is read from the ledger trail of R007, so a restart loses nothing. The limits are operator-set Fixed values in config `xrpl.limits`: `per_tx_xrp` 10, `daily_xrp` 50, `per_tx_rlusd` 10, `daily_rlusd` 50, each [0, 10000]. The kill-switch is `RiskGuard.halt` in `emerald_exchange/risk_guards.py`. While it is set, every outbound operation refuses and the result reports the halt reason. Refusals: `SPEND_LIMIT_EXCEEDED`, `KILL_SWITCH_ACTIVE`. Writes: none. Depends on: R007. | Test: `tests/test_xrpl_risk.py::test_spending_limit_and_kill_switch` (L3) asserts refusal over each limit, the restart case against a recorded trail, and the halt report. |
